# Arlington class registration — static website page

A self-contained HTML page that visualizes sellout patterns from
`../data/snapshots.sqlite`. Designed to be uploaded to any static host
(GitHub Pages, Netlify, S3, Cloudflare Pages, your existing site, etc.).

## Files

| File | Purpose |
|---|---|
| `arlington-class-registration.html` | The page itself, with the current data snapshot baked in. **This is what you upload to your website.** |
| `template.html` | Page template with a `/*__SNAPSHOT_JSON__*/` placeholder in the inline `<script>`. Edit this if you want to change copy, layout, or styling. |
| `build_snapshot.py` | Reads the sqlite database and produces a JSON snapshot of everything the page needs. |
| `build_page.py` | One-shot build script: runs `build_snapshot.py` + substitutes the result into `template.html` + writes the final HTML. **Re-run this whenever you want fresh data.** |

## Refreshing the data

From this directory:

```bash
python3 build_page.py ../data/snapshots.sqlite template.html arlington-class-registration.html
```

Or with default paths (run from the repo root):

```bash
python3 website/build_page.py
```

Then re-upload `arlington-class-registration.html` to your host. Nothing else
changes — the page has no external dependencies beyond Chart.js and Grid.js,
which it loads from the jsdelivr CDN.

To automate this on a cadence (e.g. once a day after the scraper runs), wire
it into a cron job or a GitHub Action that:

1. Runs the scraper that updates `snapshots.sqlite`.
2. Runs `python3 build_page.py`.
3. Commits/uploads the resulting HTML.

## How the page works

The page is one HTML file with three `<script>` blocks:

1. **The snapshot.** A single `window.__SNAPSHOT__ = {...}` assignment with
   all aggregated query results. About 70 KB of inline JSON. Regenerated by
   `build_page.py`.
2. **Libraries.** Chart.js v4.5 and Grid.js v5.0 loaded from jsdelivr with
   subresource-integrity hashes.
3. **Render logic.** ~400 lines of vanilla JavaScript that reads the snapshot
   and renders the charts + table. No build step, no framework, no fetch
   calls.

The snapshot shape is:

```js
{
  generated_at: "ISO timestamp when build_page.py ran",
  overall: { total, sold_out, fastest, latest_reg },
  all_times: [seconds, ...],           // for client-side median
  category_rows: [{category, secs}],   // for the category bin chart
  totals_by_cat: [{category, classes, sold_out}],
  filter_cats: [{cat, sold_out, classes}],  // dropdown population
  instant_rows: [{name, category, location, days, time_start, ages}],
  per_filter: {
    __all__: { days: [...], time: [...], age: [...], location: [...] },
    Gymnastics: { days, time, age, location },
    Aquatics: { ... },
    Tennis: { ... },
    "Sewing & Fiber Arts": { ... },
    Dance: { ... },
    Woodworking: { ... },
    __none__: { ... }  // adult fitness with empty type_label
  }
}
```

Each row in the per-filter arrays has the speed-bin counts pre-aggregated:
`b_instant`, `b_under1h`, `b_sameday`, `b_nextday`, `b_multiday`, plus
`classes`, `sold_out`, and `avg_secs`. The bin thresholds in seconds are:

- Instant: < 1200 (< 20 min — same as the scraper's polling interval, so
  this bin is effectively a measurement floor)
- Under 1h: 1200 – 3599
- Same day: 3600 – 21599 (1–6 h)
- Next day: 21600 – 86399 (6–24 h)
- Multi-day: ≥ 86400 (1d+)

## Deploying

The simplest path: drag `arlington-class-registration.html` into your
website's static asset folder, link to it from your nav, done. It's a
single self-contained file with no relative paths to worry about.

If you want a custom URL like `/registration-tracker`, rename the file to
`index.html` and place it in a `registration-tracker/` directory under your
web root.

If you're embedding inside an existing page rather than serving as its own
URL, you can iframe it:

```html
<iframe src="/path/to/arlington-class-registration.html"
        style="width:100%; height:1800px; border:0;"
        title="Arlington class registration tracker"></iframe>
```

(The page is ~1800 px tall depending on filter selections and table page
size; adjust `height` as needed.)
